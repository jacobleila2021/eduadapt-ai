# Accessibility Audit

Accessibility readiness score: 73/100. Local dashboard shell gate: zero critical/serious axe findings after fixes.

## Tested

- Chromium axe rules tagged WCAG 2 A, WCAG 2 AA, and WCAG 2.2 AA.
- Keyboard-name check for buttons.
- 320, 768, and 1440 px overflow.
- Visible focus treatment.
- Skip navigation.
- Reduced-motion and forced-colors CSS.
- SVG accessible names and valid XML.

## Fixed

- Unlabelled Streamlit sidebar toggle.
- Invalid `aria-expanded` placement generated by the framework.
- Unlabelled hidden file input.
- File-uploader helper-text contrast.
- Public exception detail exposure.

## Not yet sufficient for certification

- Full adaptation pages, LXP, notes, tutor, audio, exam, revision, and exports were not all exercised with axe.
- Screen-reader journeys were not completed with NVDA, JAWS, VoiceOver, or TalkBack.
- Keyboard order, focus restoration after reruns, 200%/400% zoom, touch targets, captions/transcripts, and reading order need manual validation.
- UDL 3.0 requires pedagogical and role-based evidence beyond CSS and ARIA checks.
- Streamlit framework DOM repairs must be regression-tested on every framework upgrade.

No WCAG or UDL certification should be claimed until the full matrix is complete.
